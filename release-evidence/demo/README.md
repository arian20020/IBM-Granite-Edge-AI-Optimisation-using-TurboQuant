# Demonstration guide

Use the verified package intended for submission. This scenario is a guide, not evidence that a new recording exists.

## Before recording

Read the [limitations](../../docs/manuals/Known-Limitations.md). Use public models and non-sensitive prompts. Check free memory and disk space, close unrelated windows and hide private notifications. Keep existing model files and exports safe.

## Short walkthrough

1. Identify the app package and the route being shown.
2. Select a model and show that import finishes.
3. Continue through model and hardware inspection.
4. Explain that compatibility is an estimate and choices depend on current resources.
5. Review an available configuration. If resources allow, run optimisation and wait for validation.
6. If export is offered, save to a new destination and show completion.
7. Open chat and send a short public prompt, such as “Explain a KV cache in two sentences.”
8. State the known limits and distinguish this demonstration from automated evidence.

Do not remove a failure from the recording and describe the journey as uninterrupted success. If it stops at compatibility, say so.

For an offline demonstration, prepare the required files first. Disconnecting Wi-Fi checks that journey without that connection; it is not a network-traffic audit.

## Save alongside the video

Record the date, package/executable hash, model name and hash, route, selected configuration, outcome and any recording edits. Add the safe video link and file checksum to the final handover. No new video or full-workflow check was performed when this guide was written.
