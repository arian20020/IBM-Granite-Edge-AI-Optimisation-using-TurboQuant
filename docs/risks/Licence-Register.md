## Purpose

This register records the licence and permitted-use position for third-party models, runtimes, libraries, forks, datasets, prompt sets, icons, fonts, copied research code, executables and other external material used by or distributed with the project.

The register distinguishes permission to research or build with a component from permission to bundle or redistribute it. A source repository licence does not automatically control every binary package, model file, transitive dependency or asset distributed with that repository.

This is an engineering compliance record, not legal advice. Any unresolved ambiguity must remain `Pending` or `Restricted` and must not be treated as permission to distribute.

## Review-status vocabulary

| Review status | Meaning |
|---|---|
| Pending | The licence or permitted-use position has not been fully reviewed. |
| Approved | Use is permitted for the stated project purpose and packaging decision. |
| Restricted | Use is permitted only under recorded conditions. |
| Rejected | The component or material must not be used or distributed in the proposed way. |
| Superseded | A later version or licence decision replaces this record. |

## Release licence gate

Before a component can be bundled into a release, the project must record:

1. the exact version, revision or package restored;
2. the authoritative licence file and any NOTICE or third-party-notice files;
3. which files will actually be distributed;
4. all attribution, modification and source-disclosure duties;
5. whether end-user terms or separate installation are required;
6. the packaging decision and reviewer;
7. a new review date when the component changes.

A component marked `Pending` must not be bundled. A component marked `Restricted` may only be used in the way stated in its packaging decision and restrictions.

Public availability, presence on GitHub, a published paper or successful technical testing does not by itself prove that modification, redistribution or packaging is permitted.
