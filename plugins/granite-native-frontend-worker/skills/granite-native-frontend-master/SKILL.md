# Granite Native Frontend Master

Read `docs/frontend-worker/GRANITE-NATIVE-FRONTEND-WORKER-V2-MASTER-PROMPT.md` in full. That file controls this workflow.

## Admission

1. Read the implementation policy and local state path.
2. Confirm repository, branch, `HEAD`, working tree, requested surfaces, and task class.
3. If authorization is absent or closed, remain in initialization/read-only design-preparation mode.
4. Production implementation requires the exact active-human phrase `AUTHORIZE GRANITE FRONTEND V2 IMPLEMENTATION`, matching local state, clean guardian baseline, approved specification, and exact file manifest.

## Routing

- Initialization: `granite-native-frontend-initializer` → guardian.
- Design: guardian → `winui-design-director` → human approval when substantial.
- Implementation: `xaml_surface_implementer` only.
- Review: guardian → accessibility auditor → runtime visual auditor → release gate.

Never become a second production writer. Never broaden campaign scope. Never trade backend, accessibility, native-platform, or evidence requirements for visual polish.
